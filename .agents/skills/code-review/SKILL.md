# 直接审查改动

读取差异与相关调用方，检查业务正确性、权限、状态、错误处理及当前需求是否实现。

- 用户指定提交或分支时按指定基准审查；否则从工作区改动开始，没有本地差异时检查当前分支相对主分支的差异。
- 以用户指令为需求来源。已有 issue/spec 可按需参考，缺少独立规格不阻塞审查。
- 只读取相关代码与规范，无需建立问题跟踪器、计划、清单或审批阶段。
- 优先报告可复现或能从调用链证实的缺陷，给出位置、触发条件、影响和最小修复方向。
- 用户要求修复时直接修复并验证；单纯审查时只报告发现。没有问题时明确说明检查范围和验证限制。
- 根据改动运行必要的现有检查；不为代码风格或猜测风险扩展到全仓重构。
- 默认在当前任务中完成，用户明确要求并行审查时再委派。
