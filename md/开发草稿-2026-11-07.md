## 本轮工程决策与使用方法

- **事务与 MQ**：保留交易本地事务，不将下单异步化；Redis Stream 与 Outbox 延后通知/ERP 同步。已有认领、租约、退避和幂等继续使用，不为简历引入额外 MQ 或拆分资金事务。
- **追踪**：HTTP 使用经过归一化的 X-Request-Id。Servlet 在准入/鉴权前绑定 MDC 并清理；Gateway 使用 exchange/Reactor context，避免响应式线程之间串用 MDC。Outbox 在原有 JSON 内附加 _traceId，重试投递到 Stream 的 traceId 字段，兼容没有 metadata 的历史事件。traceId 是诊断信息，不能当权限凭据或幂等键。
- **迁移**：旧 SQL 初始化和兼容迁移保留，顺序为初始化 → 旧迁移（order 0/100/200）→ Flyway（order 300）→ 默认顺序的种子。基线为 0，V1 检查旧升级关键列并记录校验和；以后使用各服务 db/migration 下的 V2+。主库和 ERP 的历史表各在自己的库中，禁止修改已执行迁移、自动 repair/clean 或冒称 MySQL DDL 可事务回滚。首次升级前备份，失败时保留错误与数据，向前修复。
- **观测**：保留 /internal/metrics 原接口，新增独立 Actuator 端口（app 9101、ERP 9201、Gateway 8088），默认绑定回环地址。只暴露 health/metrics/prometheus，不开放 env/configprops。Outbox 指标由定时 SQL 汇总，抓取不查询业务库；采集失败显示不可用/NaN，不伪装成积压为零。
- **监控平台**：`docker-compose.monitoring.yml` 为显式加载的可选叠加文件；Prometheus/Grafana 使用官方发布版本。业务管理端口没有宿主端口映射，叠加文件只在容器网内开放。Grafana 需要独立密码，匿名访问关闭；本机看板绑定 127.0.0.1。告警规则仅计算状态，未配置外部告警接收人，不代表已发送通知。
- **工程门禁**：保留前后端原构建回归；增加 JaCoCo 报告、真实依赖测试零跳过检查、依赖变更审查、定期依赖更新和运行镜像高危漏洞检查。镜像扫描配置忽略尚无修复的漏洞，此边界须如实说明。未获提交/推送授权，不触发外部 CI 或制造 Issue/PR 历史。
