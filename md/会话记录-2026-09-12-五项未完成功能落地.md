## 一、多规格 SKU

**数据模型**：新增 `goods_specs(id, goods_id, name, price, stock, version, sort, status, create_time)`；
`cart_items` 增 `spec_id` 并把唯一键换成 `uk_cart_user_goods_spec(user_id, goods_id, spec_id)`
（老库由 `SchemaMigration` 自动 drop 旧键 + 加新键，已在本机库验证）。

**口径**：菜品的 `price`/`stock` 始终是「启用规格的最低价 / 库存合计」，由 `StoreService.syncGoodsFromSpecs`
与 `DataSeeder` 回写，保证店铺列表、起送价、特价筛选与库存显示口径一致；下单时 goods 与规格库存**同时扣减**，
取消/超时取消**同时回滚**。

**后端**：`GoodsSpecDao`（含 `deductStock` 乐观锁条件更新）、`Goods.specs` 随商品列表返回（`IN` 批量补齐，避免 N+1）、
`CartService` 全链路带 specId、下单必须带 `specId`（无规格菜品传 0 且不接受非 0），订单 items JSON 快照 `specName`/`seckillId`。
商户端接口：`GET/PUT /api/merchant/goods/{id}/specs`（整体覆盖，保留已有规格 id）。

**前端**：`StoreDetailPage` 新增 `SpecSelectDialog`（规格名/价/剩余库存、售罄不可选、数量步进器）——
注意商品卡片所在的 `StoreDetailContent` 在 `Index.ets` 内，弹窗控制器只能挂在页面组件上，因此用
`onSelectSpecGoods` 回调把点击从内容组件传到页面再开弹窗；多规格菜品把 +/− 换成「选规格」按钮
（`−` 走的是 specId=0 的改数量接口，对多规格必然 400）。购物车行按 (菜品,规格) 唯一，
商户端新增/编辑商品页支持规格维护。

## 二、待付款支付模型 + 超时自动取消

**下单语义变化**：`POST /api/orders` 不再扣余额，只占用库存/秒杀名额并核销优惠券（记 `orders.coupon_id`），
落库 `status=0`、`pay_time=''`；返回体新增 `payDeadline = create_time + takeout.order.pay-timeout-minutes`。

**支付**：`POST /api/orders/{id}/pay`：校验余额 → 扣款 → `UPDATE ... SET status=1, pay_time=? WHERE id=? AND status=0`
（条件更新防重复支付；失败抛异常回滚余额扣减）。

**超时取消**：`OrderTimeoutJob`（`@Scheduled`，默认每分钟、启动 30 秒后首扫）扫描
`status=0 AND create_time < now-15min`，逐单条件更新 0→5 后回滚库存、秒杀名额并释放优惠券；
用户手动取消待付款订单走同一路径（不退款、escrow 保持 0）。

**其他口径**：商户订单列表过滤 `status=0`（未支付不该进入商户待处理队列）；
已支付订单取消仍按原口径即时退款（escrow 0→2 条件更新 + 退余额），但不退优惠券。

**前端**：结算页下单成功提示「15 分钟内完成支付」并跳转订单详情；订单详情页按 `payDeadline` 倒计时、
提供「立即支付 / 取消订单」，超时后自动刷新提示已取消；订单列表「待付款」卡片同样提供两个操作；
下单成功后按 (菜品,规格) 精确清理购物车行。

## 三、榜单 / 限时秒杀 / 凑单

- **榜单**：`GET /api/rankings/stores|goods`（月销量/评分、销量排序），新增 `RankingPage`（双 Tab、名次徽章、
  加载/空/错误态、下拉刷新、跳转店铺详情）；首页「排行榜」快捷入口改为进入该页。
- **限时秒杀**：新增 `seckills` 表（时间窗口 + quota/sold）；`GET /api/seckills` 返回进行中活动
  （含 `remainSeconds` 与服务端计算的名额进度）。下单时后端**自动套用秒杀价**并条件占用名额
  （`sold + n <= quota`），占不到名额自动回退原价；取消/超时取消归还名额。
  秒杀仅对**无规格菜品**生效（规格价与秒杀价语义冲突）；`DataSeeder` 为无规格热销单品种下 4 场演示活动。
  首页新增秒杀专区（秒杀价、划线原价、已抢进度、倒计时由页面级单个定时器驱动，避免每卡片一个定时器）。
- **凑单**：`GET /api/stores/{id}/bundle?amount=X` 返回起送价、差额与店内最低价菜品；
  购物车未达起送价时展示凑单卡片（还差多少 + 推荐菜品 + 去凑单）。

## 四、图文评价图片上传

- 后端：`POST /api/upload`（multipart，需 JWT）+ `FileStorageService`（本地按天分目录、5MB、扩展名/类型校验），
  `WebConfig` 注册 `/uploads/**` 静态映射（图片本身公开，无需鉴权）；目录走 `takeout.upload.dir`，已加入 .gitignore。
- 前端：`HttpClient.uploadFile` 用 `@ohos.net.http` 的 `multiFormDataList`（picker URI → `fileIo` 读成 ArrayBuffer）
  避开 axios FormData 传本地文件的不确定性；评价页接入系统图库选择器（最多 3 张）、逐张上传、
  缩略图预览与删除、上传中禁止提交，失败由页面统一提示一次（网络层 Toast 已关闭）。
