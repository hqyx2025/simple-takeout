两轮相同数据规模的持续测量使用 500 店、14,971 商品、10,000 笔合成查询订单；其中骑手订单池 **200 笔可抢订单**，本人配送记录 **1,000 笔**。六个只读接口按每秒 8 次、最多 8 个在途请求持续五分钟，每轮 2,400 次，各接口均核验非空结果。

| --- | ---: | ---: |

慢点来自范围判断反复读取带销量聚合的完整门店。配送改用不关联订单销量的轻量门店读取，同一请求内同店只判断一次；后续抢单仍重新读取当前位置并校验半径。未通过缩小结果集、关闭限流或跨请求缓存位置绕过瓶颈。优化后的五个逐分钟窗口各 480 次，均无失败；JVM／连接池每十秒采样一次，30 次采样全部取得，连接等待采样最大为 0。详见[逐次结果及采样](performance-sustained.json)、[原始失败基线](performance-sustained-before.json)和[对比条件](performance-comparison.json)。

环境保持 Windows 本机 HTTP 回环、JDK 25.0.2、MySQL 8.4.0、独立 Redis 5.0.14、应用堆 384 MiB、连接池 10 和缓存开启。合成订单只用于查询规模；优化前短暂重叠设备操作，不能据此给出严格生产性能倍数。五分钟结果也不代表校园无线网、持续午餐高峰或无限订单池容量。

图源保存在 [figures](figures/)，[screenshots](screenshots/) 仅含隔离环境合成数据。论文最新正文保守汉字计数见审计 JSON。此前验收目录根层的 734 项／214 项与较小设备集合属于首轮结果，不能和本轮简单相加。

本机复现入口：`mvn -f server/pom.xml test`、`node --test scripts/*.test.cjs` 和[设备实测指南](../../../设备实测指南.md)。本轮隔离夹具、TCP 故障代理、测量和构建脚本位于 `TemporaryCacheStorage/boundary-20261103/`；私有配置注入测试 API 与账号，不进入公开证据。测试前必须布置新的已送达未结算／已结算退款申请，不能反复审批已拒绝的申请。测试代理只连接本机隔离端口，不连接生产域名。

发布使用源码提交 `e0f6bd3` 对应的已验证业务代码。上线前主库与 ERP 库均已备份，沿用现有私有配置和数据卷；线上首页 HTTP 200、540 店目录、App／Gateway／ERP 健康及运行 JAR 哈希均已核对。HAP 与论文保存在服务器私有发布目录，哈希与本机一致，未把含开发入口的 debug HAP 放到公开静态下载地址。正式 HAP 仍不是 Release 上架包；校园实网、物理真机、学校查重／签字等边界保留。
