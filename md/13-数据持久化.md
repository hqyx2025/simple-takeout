# 13 - 数据持久化模块业务逻辑

> 涉及文件：`entry/src/main/ets/service/DataPersistence.ets`、`entry/src/main/ets/service/PreferencesHelper.ets`、`entry/src/main/ets/entryability/EntryAbility.ets`

## 一、功能概述

基于 `@ohos.data.preferences` 实现 7 类关键数据持久化，App 重启后恢复。核心亮点：**数据归一化（normalizeData）**，兼容旧版本缺字段数据，杜绝启动时 `undefined.length` 渲染崩溃。

## 二、业务逻辑判断

### 1. 持久化数据清单（PERSISTENCE_KEYS）

| 键 | 数据类型 | 归一化处理 |
|---|---|---|
| isLoggedIn | boolean | 直接使用 |
| user | User | normalizeUser（字段兜底） |
| cartItems | CartItem[] | 非数组回退空数组 |
| orderList | Order[] | normalizeOrderList（逐单修复） |
| favoriteList | Favorite[] | 非数组回退默认收藏 |
| addressList | Address[] | 非数组回退默认地址 |
| couponList | Coupon[] | 非数组回退默认券 |

> 不持久化：allUsers、allStores、allGoodsMap、claimableCoupons（内存模拟数据，重启还原默认）

### 2. 加载流程（`loadAllData()`）

```
触发：EntryAbility.onCreate（异步执行）
流程：
  1. getPrefs()：从 AppStorage 取 appContext → preferences.getPreferences
  2. 遍历 PERSISTENCE_KEYS：
     json = prefs.get(key, '')
     判断：json === ''（无记录）
       ├─ 是 → 日志"无持久化记录，使用默认值"（AppStorage 保留 initAppStorage 默认值）
       └─ 否 → JSON.parse → normalizeData(key, value) → setOrCreate 到 AppStorage
 3. 全部完成 → _persistenceReady = true
```

### 3. 归一化规则（`normalizeData`）

```
user（normalizeUser）：
  coupons / orders / storeIds 非数组 → 置 []
  balance 非 number → 0；id 非 number → 0
  username 非 string → '用户'；phone 非 string → ''

orderList（normalizeOrderList）：
  逐条检查：
  - 非对象 → 丢弃
  - id 非 number → 丢弃（缺核心字段）
  - items 非数组 → 置 []（防 ForEach/reduce 崩溃）
  - status 非 number → 置 1
  - address 缺失/非对象 → 用默认地址[0]

cartItems/favoriteList/couponList/addressList：
  - 是数组 → 原样返回
  - 非数组（null/损坏）→ 按 key 回退对应默认值
```

### 4. 保存流程（`saveAllData()`）

```
触发：每次数据变更后（登录/加购/下单/收藏等）
流程：
  1. getPrefs()
  2. 遍历 PERSISTENCE_KEYS：
     判断 AppStorage.has(key) 且值非 null → prefs.put(key, JSON.stringify(value))
  3. prefs.flush() 落盘
```

### 5. 清除流程（`clearAllData()`）

```
触发：登出（logout）
流程：遍历 PERSISTENCE_KEYS → prefs.delete → flush → _persistenceReady = false
结果：重启后不恢复旧登录态/订单等数据
```

## 三、启动时序（防崩溃关键）

```
EntryAbility.onCreate：
  1. setOrCreate('appContext')          ← 必须先于持久化/日志
  2. initLogger()
  3. loadAllData()（异步）

Index.aboutToAppear：
  4. initAppStorage()：判断 _persistenceReady
     ├─ true  → 跳过默认值初始化（用已恢复数据）
     └─ false → 写入默认值兜底

双保险：无论持久化成功与否，AppStorage 均有数据 → 渲染不崩溃
```

## 四、边界与异常处理

| 场景 | 处理方式 |
|---|---|
| appContext 未设置 | getPrefs 抛错 → loadAllData catch → Error 日志 |
| JSON 解析失败 | catch → Warn 日志 → 保留默认值 |
| 旧版本缺字段 | normalize 逐字段兜底修复 |
| 损坏非数组数据 | 按 key 回退默认值 |
| 保存失败 | catch → Error 日志（内存数据不受影响） |

## 五、关键日志埋点

| 事件 | 日志 | 级别 |
|---|---|---|
| 恢复成功 | `恢复数据 key=xxx 成功` | Info |
| 无记录 | `恢复数据 key=xxx 无持久化记录，使用默认值` | Info |
| 解析失败 | `恢复数据 key=xxx 解析失败，使用默认值` | Warn |
| 加载完成 | `持久化数据全部加载完成` | Info |
| 保存完成 | `数据保存完成（全部 key）` | Info |
| 清除完成 | `持久化数据已全部清除` | Info |
| 异常 | `加载/保存持久化数据失败` | Error |
