# 11 - 评价模块业务逻辑

> 涉及文件：`entry/src/main/ets/pages/ReviewPage.ets`、`entry/src/main/ets/service/AppStorageManager.ets`、`entry/src/main/ets/components/RatingStars.ets`

## 一、功能概述

用户对已完成订单进行评价（星级评分 + 标签 + 文字），提交后评价进入店铺评价列表，订单标记"已评价"防止重复评价。

## 二、业务逻辑判断

### 1. 提交评价（`addReview(review)`）

```
处理：
  1. review.id = Date.now()（唯一）
  2. reviews.unshift(review)（最新评价置顶）
  3. 标记订单已评价：
     orders.find(o => o.id === review.orderId)
     ├─ 找到 → order.remark += ' [已评价]'（复用 remark 字段打标）
     └─ 未找到 → 跳过
  4. saveAllData()
```

| 判断项 | 规则 | 结果 |
|---|---|---|
| 评价 ID | Date.now() | 唯一 |
| 最新在前 | unshift 插入头部 | 评价列表新评优先 |
| 订单打标 | find(orderId) | remark 追加" [已评价]" |

> ⚠️ 实现说明：订单"已评价"状态通过修改 remark 字段标记（无独立字段），订单详情/列表依据 remark 包含"[已评价]"来判断是否显示"去评价"按钮。

### 2. 评价评分范围校验

```
规则：RatingStars 组件限制 rating 为 1~5 整数
  - 星级点击选择（1 星起步，通常不允许 0 星）
  - 提交前判断 rating 是否有效
```

### 3. 店铺评价列表（`getStoreReviews(storeId)`）

```
逻辑：reviews.filter(r => r.storeId === storeId)
用途：店铺详情页展示评价 Tab（含默认模拟评价 + 用户新增评价）
```

## 三、边界与异常处理

| 场景 | 处理方式 |
|---|---|
| reviewList 未初始化 | `|| getDefaultReviews()` 兜底 |
| 订单不存在 | find 无结果 → 不打标，评价仍正常提交 |
| 重复评价同一订单 | 依赖订单"已评价"标记隐藏入口（提交入口防重复） |
| 评价内容为空 | 页面校验或允许空文字仅星级（按页面实现） |

## 四、数据流向

```
订单详情"去评价"（仅已完成且未评价订单）
  → ReviewPage 填评分/标签/文字
  → addReview → reviewList（AppStorage）+ 订单打标
  → saveAllData() 持久化
  → 店铺详情 getStoreReviews 展示
```
