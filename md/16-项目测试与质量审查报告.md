## 5. P0 阻塞问题

### QA-P0-001 订单详情接口存在越权读取

- 类型：访问控制 / 隐私泄露
- 证据：
  - `server/src/main/java/com/example/takeout/controller/OrderController.java:47`
  - `server/src/main/java/com/example/takeout/service/OrderService.java:134-136`
- 现状：`GET /api/orders/{id}` 只根据订单 ID 查询，没有校验订单是否属于当前用户或当前商户。
- 风险：任意登录用户枚举订单 ID 后，可读取其他用户的商品、金额、收货人、手机号和详细地址。
- 复现建议：用户 A 创建订单并记录 ID；用户 B 登录后请求用户 A 的订单 ID。
- 期望：用户只能读取自己的订单；商户只能读取自己店铺的订单。
- 修复建议：Controller 传入 `userId` 和 `role`，Service 根据用户身份和订单归属做授权校验。

### QA-P0-002 负数商品数量可造成订单金额为负、用户余额反增

- 类型：资金安全 / 参数校验
- 证据：
  - `server/src/main/java/com/example/takeout/service/OrderService.java:65-79`
  - `server/src/main/java/com/example/takeout/service/OrderService.java:94-101`
- 现状：服务端仅检查商品列表非空，没有检查 `quantity > 0`。金额直接使用数据库价格乘客户端数量。
- 风险：提交负数数量后，`payAmount` 可能为负；执行 `balance - payAmount` 时反而增加用户余额。
- 期望：数量必须是合理正整数；应付金额不得小于 0；所有资金变更必须有服务端强校验。
- 修复建议：校验数量范围、商品状态、商品店铺归属，并对最终金额做非负断言和事务测试。

### QA-P0-003 优惠券金额和门槛由客户端自行提交

- 类型：业务安全 / 资金安全
- 证据：
  - `server/src/main/java/com/example/takeout/controller/UserCenterController.java:44-45`
  - `server/src/main/java/com/example/takeout/controller/UserCenterController.java:106`
  - `server/src/main/java/com/example/takeout/service/UserCenterService.java:57-65`
- 现状：领取优惠券时，客户端可以直接提交名称、门槛和优惠金额；服务端只校验金额大于 0。
- 风险：用户可构造超大金额优惠券，结合订单计算使应付金额变为负数。
- 期望：客户端只能提交活动 ID；金额、门槛、适用店铺和有效期必须由服务端活动配置决定。
- 修复建议：建立优惠活动表，领取接口只接收活动 ID，并校验领取次数、用户范围、库存和有效期。

### QA-P0-004 地图选址生成的地址无法完成真实后端下单

- 类型：核心功能 / 数据一致性
- 证据：
  - `entry/src/main/ets/pages/LocationPage.ets:296`
  - `entry/src/main/ets/pages/CheckoutPage.ets:108-110`
  - `server/src/main/java/com/example/takeout/service/OrderService.java:68-72`
- 现状：地图确认位置保存为 `id: 0`，结算页将该 ID 发送给后端；服务端要求地址 ID 必须属于当前用户且真实存在。
- 影响：用户在主页选择地图位置后，看似地址已确认，但提交订单会得到“收货地址不存在”。
- 期望：地图位置确认后应先新增或更新服务端地址，并使用服务端返回的地址 ID 下单。
- 修复建议：地图确认时调用地址新增接口，保存经纬度和结构化地址；接口成功后再写入 `currentAddress`。

### QA-P0-005 注册接口返回密码哈希

- 类型：敏感信息泄露
- 证据：
  - `server/src/main/java/com/example/takeout/model/User.java:11`
  - `server/src/main/java/com/example/takeout/service/AuthService.java:50`
  - `server/src/main/java/com/example/takeout/controller/AuthController.java:27-28`
- 现状：注册服务返回数据库插入后的 `User`，其中 `password` 字段包含哈希值；只有登录接口调用了 `safe()`。
- 风险：密码哈希会通过注册响应暴露，增加离线破解和日志泄露风险。
- 期望：所有用户响应 DTO 均不得包含密码或密码哈希。
- 修复建议：注册接口同样返回 `user.safe()`，最好彻底拆分数据库实体和外部响应 DTO。

### QA-P0-006 密钥、数据库密码和 HTTP 地址硬编码

- 类型：配置安全 / 传输安全
- 证据：
  - `server/src/main/resources/application.yml:10`
  - `server/src/main/resources/application.yml:24`
  - `entry/src/main/ets/common/Constants.ets:111`
- 现状：数据库 root 密码和 JWT 密钥提交在仓库中；客户端使用明文 HTTP。
- 风险：密钥泄露后可伪造 JWT；公网环境中账号、密码、Token、地址和订单信息可被窃听。
- 修复建议：使用环境变量/密钥服务注入配置，立即轮换已提交的密钥，生产环境强制 HTTPS。

## 6. P1 严重问题

### QA-P1-001 选择错误角色后，应用已经写入登录态

- 证据：
  - `entry/src/main/ets/service/AppStorageManager.ets:609-614`
  - `entry/src/main/ets/pages/LoginPage.ets:162-168`
- 现状：`loginRemote` 成功后立即写入 `user` 和 `isLoggedIn=true`，页面随后才判断所选角色是否匹配。
- 影响：页面显示“账号角色不匹配”，但全局状态已经登录成功，可能通过返回或切换页面进入已登录功能。
- 修复建议：登录服务只返回用户和 Token；角色校验通过后再一次性提交登录状态，失败时清理 Token。

### QA-P1-002 Token 不持久化，但登录状态被持久化

- 证据：
  - `entry/src/main/ets/service/HttpClient.ets:14-17`
  - `entry/src/main/ets/service/DataPersistence.ets:15-23`
- 现状：JWT 只保存在内存变量中；`isLoggedIn` 和 `user` 会持久化。
- 影响：应用重启后 UI 显示已登录，但所有需要鉴权的请求都会因没有 Token 返回 401。
- 修复建议：使用安全存储保存 Token；启动时验证 Token/刷新会话；验证失败应原子化退出登录。

### QA-P1-003 任何普通用户都可以调用商户创建店铺接口

- 证据：
  - `server/src/main/java/com/example/takeout/security/AuthInterceptor.java:39`
  - `server/src/main/java/com/example/takeout/controller/StoreController.java:67-70`
  - `server/src/main/java/com/example/takeout/service/StoreService.java:66-73`
- 现状：JWT 中解析了角色，但商户接口没有校验 `role == 1`。
- 影响：普通用户可以创建店铺，随后成为该店铺 owner 并使用商户管理接口。
- 修复建议：在商户 Controller/Service 或统一权限注解中校验角色，并增加越权测试。

### QA-P1-004 商户完成订单后没有增加商户余额

- 证据：`server/src/main/java/com/example/takeout/service/OrderService.java:156-179`
- 现状：订单完成只更新状态和完成时间，没有给店铺所属商户结算收入。
- 影响：用户余额已扣除，但商户余额不变；客户端 Mock 逻辑和真实后端逻辑不一致。
- 修复建议：在完成订单的事务中增加商户结算，并设计平台抽佣、退款冲正和重复结算保护。

### QA-P1-005 服务端没有校验起送价、店铺营业状态和商品上架状态

- 证据：
  - `server/src/main/java/com/example/takeout/service/OrderService.java:63-102`
  - `server/src/main/java/com/example/takeout/service/StoreService.java:40-54`
- 影响：用户可能购买已下架商品、向休息中的店铺下单，或订单金额低于起送价。
- 修复建议：下单时校验店铺状态、商品状态、商品所属店铺、起送价、数量上限和库存。

### QA-P1-006 优惠券未校验有效期和适用店铺，取消订单后不返券

- 证据：`server/src/main/java/com/example/takeout/service/OrderService.java:82-93`
- 现状：只校验优惠券属于用户、未使用和满足门槛，没有校验过期时间及店铺范围。
- 影响：过期券、其他店铺券可能被使用；取消订单后用户永久损失优惠券。
- 修复建议：校验有效期和适用范围；取消/退款时根据业务规则返券。

### QA-P1-007 地址编辑只改本地，不更新后端

- 证据：`entry/src/main/ets/pages/AddressListPage.ets:368-375`
- 现状：编辑地址时直接修改 `AppStorage`，没有调用服务端更新接口。
- 影响：退出页面或重新同步后修改丢失；下单仍使用服务端旧地址。
- 修复建议：补充地址更新 API，保存成功后再刷新列表并提示结果。

### QA-P1-008 后端地址转换导致地址重复显示

- 证据：`entry/src/main/ets/service/ApiService.ets:628-635`
- 现状：后端只有 `detail` 字段，客户端转换时同时赋给 `address` 和 `detail`。
- 影响：结算页使用 `${address} ${detail}`，同一地址会显示两遍。
- 修复建议：后端拆分省市区和详细地址，或客户端只将完整地址赋给一个字段。

### QA-P1-009 个人资料修改只保存在客户端

- 证据：
  - `entry/src/main/ets/pages/ProfileEditPage.ets:44-57`
  - `entry/src/main/ets/service/AppStorageManager.ets:583-599`
  - 服务端 `AuthController` 只有 `/me` 查询，没有资料更新接口
- 影响：用户看到“保存成功”，但重新登录或换设备后昵称和手机号恢复旧值。
- 修复建议：新增资料更新接口，后端校验手机号唯一性；成功后再更新本地状态。

### QA-P1-010 隐私同意前已经初始化日志、持久化并发起网络请求

- 证据：
  - `entry/src/main/ets/entryability/EntryAbility.ets:20-23`
  - `entry/src/main/ets/pages/Index.ets:151-155`
  - `entry/src/main/ets/pages/Index.ets:314`
- 影响：隐私弹窗只是覆盖在界面上，日志初始化、数据读取和店铺网络同步可能已经发生，不符合“同意后处理必要信息”的预期。
- 修复建议：将非必要初始化和网络行为放到同意回调之后；拒绝时提供基础离线浏览或退出路径。

### QA-P1-011 日志文件记录手机号、地址、评价正文等个人信息

- 证据：
  - `entry/src/main/ets/service/AppStorageManager.ets:77-104`
  - `entry/src/main/ets/service/AppStorageManager.ets:322`
  - `entry/src/main/ets/service/AppStorageManager.ets:433`
  - `entry/src/main/ets/pages/LocationPage.ets:307`
- 影响：日志长期保存在应用沙箱并可导出，形成额外隐私数据副本。
- 修复建议：手机号和地址脱敏；禁止记录评价全文、Token、密码和精确坐标；Release 关闭业务明细日志并设置保留期限。

### QA-P1-012 应用允许备份恢复，但未配置个人数据排除规则

- 证据：`entry/src/main/resources/base/profile/backup_config.json:2`
- 影响：用户、订单、地址和日志可能进入备份，增加跨设备和云端泄露面。
- 修复建议：根据业务需求禁用备份，或明确排除 Token、日志、地址和账户敏感数据。

### QA-P1-013 搜索接口注释为游客放行，实际仍要求登录

- 证据：
  - `server/src/main/java/com/example/takeout/config/WebConfig.java:26-34`
  - `server/src/main/java/com/example/takeout/controller/UserCenterController.java:99-103`
- 现状：拦截器白名单没有 `/api/search`。
- 影响：未登录用户搜索时远程请求返回 401，客户端静默回退本地 Mock，掩盖真实接口错误。
- 修复建议：明确搜索是否公开；若公开则加入白名单，若需登录则客户端应明确提示。

### QA-P1-014 客户端真实后端和本地 Mock 混用，失败时会产生“假成功感”

- 现状：首页、搜索和部分列表在后端失败时继续展示 Mock 数据，但下单、收藏和地址等操作走真实后端。
- 影响：用户能浏览并加入购物车，却在后续操作突然失败；测试人员也容易误判系统已联通。
- 修复建议：构建时明确区分 Mock/开发/生产环境；真实后端模式失败时展示可恢复的错误页，不自动混入 Mock 业务数据。

### QA-P1-015 服务端没有任何自动化测试

- 证据：Maven 输出 `No tests to run`
- 影响：本报告发现的权限、金额和优惠券问题无法被回归保护。
- 修复建议：优先补充 `OrderService`、`AuthService`、权限拦截和 Controller 集成测试。

## 7. P2 一般问题与人性化问题

### QA-P2-001 登录页缺少提交中状态和防重复点击

- 现状：登录/注册按钮没有 `loading` 或 `submitting` 状态。
- 影响：弱网下用户可能重复点击，发起多次注册或登录请求。
- 建议：请求期间禁用按钮，显示加载提示，并区分网络错误、账号错误和服务端错误。

### QA-P2-002 注册失败提示不准确

- 证据：`entry/src/main/ets/pages/LoginPage.ets:173-182`
- 现状：所有注册失败最终都提示“该手机号已注册”。
- 影响：密码过短、手机号格式错误、服务器异常都会误导用户。
- 建议：将服务端业务错误消息安全映射到对应表单字段。

### QA-P2-003 删除地址没有二次确认和明确结果

- 证据：`entry/src/main/ets/pages/AddressListPage.ets:158`
- 影响：误触后直接删除；弱网失败时用户不知道操作是否生效。
- 建议：增加确认弹窗、加载态、成功/失败提示和失败回滚。

### QA-P2-004 地址保存和设为默认未等待异步结果

- 证据：`entry/src/main/ets/pages/AddressListPage.ets:341-385`
- 影响：界面先关闭或先修改本地状态，远程失败时本地与服务端不一致。
- 建议：所有远程操作 `await` 后再更新 UI，并提供重试入口。

### QA-P2-005 没有无障碍描述和稳定的 UI 自动化标识

- 静态扫描结果：主 ETS 代码中无障碍标记数量为 0。
- 影响：读屏用户难以理解图标；UiTest 难以稳定定位控件。
- 建议：为图标、按钮和输入框增加无障碍文本、组件 ID 和明确的可点击语义。

### QA-P2-006 大量 Emoji 和 Text 被当作交互图标

- 影响：不同字体和设备显示可能不一致，点击区域和读屏语义不明确，不符合正式产品一致性要求。
- 建议：使用统一 SVG/资源图标和标准 Button/Image 交互组件。

### QA-P2-007 大量样式硬编码，主题与大屏适配风险高

- 静态扫描发现约 110 处数字或颜色硬编码样式。
- 影响：深色模式、字体缩放、2in1 大屏和统一改版成本较高。
- 建议：继续收敛至资源文件和 `Constants.ets`，增加横屏、折叠屏和字体放大测试。

### QA-P2-008 废弃 API 使用较多

- 静态扫描发现约 80 处 `pushUrl`、`router.back`、`showToast`、`getContext` 相关调用。
- 影响：后续 SDK 升级可能出现兼容性问题，构建警告噪声也会掩盖新问题。
- 建议：统一迁移至当前推荐路由、提示和上下文 API。

### QA-P2-009 设置中的“清除缓存”实际只清空购物车

- 证据：`entry/src/main/ets/pages/SettingsPage.ets:27-40`
- 影响：用户可能误以为图片、搜索历史和日志都被清除；购物车却属于业务数据，不应被含糊地称为缓存。
- 建议：将其改名为“清空购物车”，或真正清理可再生成缓存并明确列出范围。

### QA-P2-010 搜索远程返回 0 条时会回退本地结果

- 证据：`entry/src/main/ets/pages/SearchPage.ets:45-51`
- 影响：无法区分“后端正常返回无结果”和“后端请求失败”，用户看到的结果可能与服务器数据不一致。
- 建议：网络层返回明确的成功/失败状态，不要用空数组同时表示两种情况。

### QA-P2-011 存在未使用且含硬编码用户地址的旧下单逻辑

- 证据：`entry/src/main/ets/pages/Index.ets:1043` 附近的 `submitOrder()`。
- 影响：代码中仍保留“张三、固定手机号、清华地址”的旧 Mock 下单实现，易被后续维护者误调用。
- 建议：删除死代码，所有订单创建只保留一个真实服务端入口。

### QA-P2-012 启动时持久化加载与默认数据初始化存在竞态

- 证据：
  - `entry/src/main/ets/entryability/EntryAbility.ets:23`
  - `entry/src/main/ets/pages/Index.ets:107-113`
- 现状：`loadAllData()` 异步调用但未等待，页面可能先执行 `initAppStorage()` 写入默认值。
- 影响：可能出现首页短暂展示默认用户/Mock 数据，之后再被持久化数据覆盖。
- 建议：增加统一启动状态，在持久化完成后再加载主页面或渲染业务内容。

## 8. 推荐补充的测试用例

### 8.1 P0 自动化回归用例

| 用例 ID | 场景 | 预期 |
|---|---|---|
| SEC-001 | 用户 B 查询用户 A 的订单详情 | 返回 403，不返回订单和地址 |
| SEC-002 | 普通用户调用创建店铺接口 | 返回 403 |
| SEC-003 | 注册接口响应 | 响应中不存在 password 字段或字段为空 |
| ORD-001 | 商品数量为 0、负数、超大值 | 请求被拒绝，余额不变化 |
| ORD-002 | 优惠后金额小于 0 | 请求被拒绝或金额安全归零，不得增加余额 |
| ORD-003 | 下架商品、休息店铺、未达起送价 | 请求被拒绝并返回明确原因 |
| COUPON-001 | 客户端伪造优惠金额 | 服务端忽略客户端金额并按活动配置处理 |
| COUPON-002 | 过期券、其他店铺券 | 不可使用 |
| ADDR-001 | 地图位置确认后下单 | 服务端存在有效地址 ID，订单创建成功 |

### 8.2 核心端到端用例

1. 用户注册 → 登录 → 选择位置 → 添加地址 → 选择店铺 → 加购 → 使用优惠券 → 下单。
2. 商户登录 → 查看所属店铺订单 → 接单 → 出餐 → 完成。
3. 用户刷新订单 → 确认收货 → 评价 → 店铺评价列表可见。
4. 用户取消待接单订单 → 余额恢复 → 优惠券按规则恢复。
5. 杀进程并重启 → 登录态和 Token 一致 → 鉴权请求成功。
6. Token 过期 → 自动退出或刷新 Token → 不出现“界面已登录、接口全失败”。

### 8.3 异常与人性化用例

- 无网络、超时、后端 500、Token 过期、地图脚本加载失败。
- 定位权限拒绝、永久拒绝、系统定位关闭、定位超时。
- 连续快速点击登录、注册、提交订单、领券、删除地址。
- 返回键、手势返回、前后台切换、旋转屏幕、2in1 窗口缩放。
- 字体放大、深色模式、读屏模式、焦点导航。
- 订单列表 1000 条、商品列表 1000 条、日志文件轮转和低存储空间。

## 9. 修复优先级建议

### 第一阶段：安全与资金阻塞

1. 修复订单详情越权。
2. 服务端校验数量、金额、店铺、商品、起送价和库存。
3. 重构优惠券领取与核销规则。
4. 移除注册响应中的密码哈希。
5. 轮换 JWT/数据库密钥并启用 HTTPS。

### 第二阶段：打通真实核心链路

1. 地图地址落库并获得服务端地址 ID。
2. 修复登录角色校验和 Token 恢复。
3. 修复地址编辑、资料编辑、商户结算和优惠券返还。
4. 分离 Mock、开发和生产环境。

### 第三阶段：人性化与隐私

1. 隐私同意前停止非必要网络、日志和数据处理。
2. 日志脱敏并配置备份排除。
3. 增加加载态、防重复点击、确认弹窗、错误分类和重试入口。
4. 完善无障碍语义和多设备适配。

### 第四阶段：质量门禁

1. 为服务端新增单元测试和接口集成测试。
2. 将客户端函数覆盖率提升到至少 60%，核心服务达到 80%。
3. 增加 3 至 5 条关键 UI 自动化链路。
4. 执行 Code Linter、AppAnalyzer、真机稳定性和 Release 签名测试。
