## 当前实现

### 售后、结算与债务

送达后 48 小时内，订单即使已确认收货、结算或评价，也可在剩余实付范围申请部分 / 全额退款。用户提交原因、说明和最多 9 张已上传相对地址图片，商家可以举证，仍只由管理员裁决。被驳回后 48 小时内可以申诉一次，不能换请求号重新开申请绕过限制。同一已受理申请标识始终映射原申请。

售后待审保存原结算阶段；部分退款回到已送达状态并保留原 escrow，累计全额退款才进入 status=6 / escrow=2。已送达餐品不恢复可售库存。结算后商户累计承担不超过原净结算部分，先扣可用余额，不足记待偿，不产生负余额；骑手既有收入不扣回，差额记录平台售后成本。后续结算按 FIFO 抵扣待偿，再将余款入钱包，结算、偿债和售后台账可核对。

实现证据：[AfterSalesService](../../server/takeout-app/src/main/java/com/example/takeout/service/AfterSalesService.java)、[AfterSalesDao](../../server/takeout-app/src/main/java/com/example/takeout/dao/AfterSalesDao.java)、[售后接口](../../server/takeout-app/src/main/java/com/example/takeout/controller/AfterSalesController.java)。

### 外部退款意图与恢复

外部渠道副作用不能随数据库回滚。调用渠道前，独立 REQUIRES_NEW 事务向无外键退款意图表保存稳定退款号、AFTER_SALES / CANCEL / LATE 类型、订单 / 支付 / 售后标识、实际退款金额、原总额、已校验渠道交易号与取消责任元数据；该事务不更新主事务已锁的订单、退款或支付行。

意图先为 REQUESTED，渠道确认后独立记 CONFIRMED，本地业务事务 afterCommit 后记 DONE。渠道成功但本地事件 / 台账失败时，意图保留，后台每轮最多 20 条恢复原审批、取消或迟到支付退款，失败留待后续处理。恢复始终沿用原退款号、金额和责任政策。当前锁定读保护驳回与履约：已有渠道意图的售后不能再驳回，未完成 CANCEL 意图阻止继续履约。余额退款仍走本地事务，不创建外部意图。

实现证据：[ExternalRefundAttemptService](../../server/takeout-app/src/main/java/com/example/takeout/service/ExternalRefundAttemptService.java)、[ExternalRefundRecoveryJob](../../server/takeout-app/src/main/java/com/example/takeout/job/ExternalRefundRecoveryJob.java)。独立售后 DDL 与主 schema 同步，旧库迁移幂等补结构，不移动资金或伪造历史。

### 责任取消、营销与真实统计

未支付取消释放库存、秒杀名额、优惠券和新客占用；已支付用户主动取消不返券，商家 / 平台取消退回仍有效券。仅接单前恢复可售库存，制作、配送后取消及已送达售后不回可售库存。取消来源与原因用于原渠道退款恢复，不在重试时改责任。

营销固定为确定性最优折扣 → 本店首笔成功支付新客立减 → 优惠券；折扣同值按活动 ID，新客取最大立减、同值按 ID，赠品门槛用折扣后商品额。新客资格在下单时持久占用、支付后使用、未支付取消释放，已成功支付不因退款恢复为新客。订单保留定价快照，客户端仅展示预估。

近 30 天销量按支付时间统计，商品按 order_items 数量、门店按已支付订单数，排除待付款、取消和累计全额退款，不混入 seed 或手工累加月销量。商户收入按实际净结算计入结算日，结算前退款已从净额扣除；结算后商户承担退款在退款日扣回，不能以订单创建日重写收入，也不能仅按当前终态筛选漏掉已结算后全退。

实现证据：[OrderService](../../server/takeout-app/src/main/java/com/example/takeout/service/OrderService.java)、[PromotionService](../../server/takeout-app/src/main/java/com/example/takeout/service/PromotionService.java)、[GoodsDao](../../server/takeout-app/src/main/java/com/example/takeout/dao/GoodsDao.java)、[OrderDao](../../server/takeout-app/src/main/java/com/example/takeout/dao/OrderDao.java)。

### 配送与 App / Web 契约

门店可设置 RIDER / MERCHANT，下单保存配送快照，之后改设置只影响未来订单。骑手模式出餐后进入骑手池，商家自配送不进入池且由商家推进配送 / 送达。履约中可持久上报无人接单、联系不上、地址问题、餐损等异常；平台分页核对并选择改派、继续或取消，改派限骑手模式取餐前。

客户端以 capabilities.allowedActions 为动作权威，存在时空或畸形值禁操作，仅能力字段缺失才兼容旧规则；服务端仍校验角色、归属、状态与金额。App 分页失败保留数据、提供重试；账号、页面和请求版本隔离迟到响应，上传 401 刷新后最多重试一次，避免重复提示。Web 更新新客、取消、售后证据、商家待偿与配送异常入口。自取和预约仍未开放。

实现证据：[OrderOperationsService](../../server/takeout-app/src/main/java/com/example/takeout/service/OrderOperationsService.java)、[配送接口](../../server/takeout-app/src/main/java/com/example/takeout/controller/OrderOperationsController.java)。

### ERP 采购与付款审计

物料 / 供应商支持服务端分页搜索和选择，关联供应商筛选随翻页刷新保留。结果未知的写请求在发送前，以账号 + 门店隔离的 sessionStorage 保存原 key 和 payload，离开重进或切店返回后核对原内容、显式重试；损坏记录禁写并保留，不保证浏览器会话结束后恢复。

付款凭证纠错、错误付款冲销、实际供应商退款均追加审计并保留原记录；净已付扣除冲销 / 退款，与有效收货应付及收货冲销限制闭合。付款只是线下凭证登记，不从应用钱包转账。ERP 仍独立数据库，管理非食材耗材，不实现食材配方或按菜品销量自动扣料。

实现证据：[ERP 页面](../../server/takeout-gateway/src/main/resources/static/erp.js)。
