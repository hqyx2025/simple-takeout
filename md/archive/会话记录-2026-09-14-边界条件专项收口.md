## 一、审计方法

1. **分域并行审计**：后端核心链路（下单/支付/取消/退款/结算）、Web 层与接口边界（参数绑定、
   上传、错误码、权限）、前端 ArkTS（解析、空值、下标、精度）分域并行排查，各自给出
   「确定缺陷 / 需用户决策」两类结论。
2. **主线自读复核**：对资金与状态流转路径逐条读代码，确认「先查后改」「读余额改整值写回」
   这类无法靠单点阅读判定的并发边界。
3. **口径先问后改**：涉及业务口径（起送价归属、券后 0 元单、超时宽限、退款终态）的一律先提问，
   不擅自决定；已确定口径写进 `AGENTS.md` 第 11 节，防止后续被"改回去"。

## 二、修复的高危缺陷（后端）

### 资金与状态机

| 缺陷 | 后果 | 处理 |
| --- | --- | --- |
| 支付/退款走「读余额 → 改 → 整值写回」 | 并发支付互相覆盖，等于免费吃饭 | 新增条件扣款 `UserDao.deductBalance`（`WHERE balance >= ?`）与原子自增 `addBalance`，**删除** `updateBalance` |
| `AdminService.refundOrder` 对 status=0/5 也退款 | 对从未扣款的订单凭空加余额 + 重复回滚库存 | 限定 status ∈ {1,2,3}，已送达走审批、未支付直接拒绝 |
| 状态流转「先查后改」 | TOCTOU 可留下 `status=2 + escrow=2` | 统一条件更新：`updateStatusFrom`/`markRefunding`/`merchantDeliver`/`merchantComplete`，rowcount=0 抛错整单回滚 |
| 管理端退款路径漏回滚规格库存与秒杀名额 | 库存/名额永久泄漏 | 统一走 `OrderService.rollbackStock` |
| `applyRefund` 先落记录再改状态 | 重复点击产生第二条 PENDING 退款单 | 先 4→6 条件流转成功，再写记录 |
| 骑手送达的单量与收入不在同一事务 | 送达成功但骑手收入丢失 | 并入 `OrderService.riderDeliver` 事务；删除 `RiderService.recordDelivered` |
| 停用骑手仍可抢单/取餐/送达 | 停用账号继续接单 | `requireOnlineRider` 增加 `status != 1` 拒绝 |

### 数值与金额

- 结算勾选按菜品去重（同一菜品多规格重复上报 `goodsId` 原先必然被拒）、起送价只算本店商品
  （原先可用跨店金额凑门槛）。
- 购物车数量改 long 累加判上限（`1 + Integer.MAX_VALUE` 溢出成负数可绕过库存校验）。
- `Store.haversine` 把余弦值夹到 [0,1]（浮点误差致 NaN，NaN 距离会让店铺被静默过滤）。
- 门店配送费/起送价拒绝非有限值（NaN/Infinity 绕过校验；负数仍表示"不修改"）。
- **券后应付为 0 元的订单服务端一律拒绝**（差额不退），结算页可用券列表同步过滤此类券。

### 输入校验与错误语义

- 参数绑定失败 / 缺参 / 坏 JSON / 缺 multipart / 上传超限 → **400**（原先统一 500「服务器内部错误」）；
  上传超限给「图片大小不能超过 5MB」。
- 上传 `content-type` 由「为 null 即跳过校验」改为**必填 + 精确白名单**。
- 文本列宽全部在服务层拦截（超长原先由 MySQL 列宽溢出变成 500）：
  用户名 64 / 店铺名 128 / 店铺公告·地址 512 / 配送时间 32 / 商品名 128 / 商品描述 512 /
  商品图片 255 / 商品标签 32 / 规格名 64 / 分类名 32 / Banner 标题 64·副标题 128·图 255·跳转参数 128 /
  公告标题 128·内容 1024 / 订单备注 255 / 评价内容 512 / 退款原因 255 / 地址姓名 64·详情 255。
- `updateBanner` 不再接受空白标题（旧语义把 null 一律当空串覆盖，只改 sort 的 PUT 会清空标题；
  前端只有 create/status/delete 三个调用，无破坏面）。
- 领域事件去重键改为**处理成功后才写**：先写会让「处理失败但未 ACK」的事件在重读时被判重复而永久丢弃。

### 时间与超时

- 核查时钟源：`docker-compose`、`server/Dockerfile`、JDBC `serverTimezone`、Jackson `time-zone`
  全部为 Asia/Shanghai，SQL 中**无 `NOW()`/`CURRENT_TIMESTAMP`**，种子数据的时间全部相对
  `LocalDateTime.now()` 生成 → 不存在 JVM 与数据库、Java 与种子数据之间的时区/时钟偏移。
- `OrderDao.listExpiredPending` 增加单轮 `LIMIT 500`：极端积压时不把全部待付款订单读进内存
  （`ponytail:` 注释标明上限与升级路径）；取消本身是条件更新，天然幂等。

## 三、修复的高危缺陷（前端 ArkTS）

| 缺陷 | 后果 | 处理 |
| --- | --- | --- |
| 过期券（`status===2`）被列为可用券 | 选中后下单**必然失败** | `ApiService` 改 `used: c.status !== 0`；结算页过滤 `amount >= 商品总价` 的券 |
| 退出登录不清 `selectedCoupon` | 换账号后沿用上一账号的券，下单失败 | 登出同时清 `selectedCoupon`/`couponList`/`orderList` |
| 结算金额用 `goods.price` 而非行内规格价 | 多规格菜品预估金额小于实际 | 两处合计函数统一改 `(x.price ?? x.goods.price)` |
| `clearAllData` 删除 `privacyConsent` | 冷启动隐私同意状态丢失 | 跳过 `privacyConsent` |
| 持久化地址未归一，`currentAddress.address.trim()` | 旧数据导致冷启动白屏 | 新增 `normalizeAddress`/`normalizeAddressList` 并接线 |
| ForEach key 未含 `specId` | 同菜品多规格列表项复用错乱 | key 改 `${item.goods.id}_${item.specId ?? 0}` |
| `o.createTime.startsWith(...)` 空值 | 持久化数据缺字段时崩溃 | 改 `(o.createTime ?? '').startsWith(...)` |
| 商户配送费/起送价用 `|| 3` 解析 | 合法值 0 被吞成 3 | 空串取默认、非有限值/负数拒绝 |
| 结算页「所有店合计 vs 最大起送价」前置拦截 | 与服务端逐店校验口径矛盾，提示自相矛盾 | 删除前端前置校验与死代码 `getCheckoutMinOrder()`，起送价只信服务端 |
