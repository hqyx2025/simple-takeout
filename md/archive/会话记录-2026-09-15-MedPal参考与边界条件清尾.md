## 本轮完成的 9 项修复

### 1. 搜索 N+1 问题 → `d936ff3`
- `UserCenterService.search` 原先逐店查商品（41 店 → 42 次查询）
- 改为一条 `SELECT DISTINCT store_id FROM goods WHERE name LIKE ?`
- 契约由 `UserCenterSearchTest.searchNeverQueriesGoodsPerStore` 钉住

### 2. 平台统计口径统一 → `7b43be1`
- `AdminStatsDao.today_orders` 补排除 status 5/6（与 `today_gmv` 同口径）
- 趋势 `order_count` 从 `COUNT(*)` 改为 `COUNT(CASE WHEN status NOT IN (5,6) THEN 1 END)`
- 新增 `AdminStatsDaoSqlTest`（3 用例）钉住口径
- `total_orders` 故意保留全状态（展示"累计下单数"）

### 3. merchantStats 删除 range 参数 → `7b43be1`
- `GET /api/merchant/stats?storeId=` 的 `range` 参数从未使用
- 响应固定返回今日/本周/本月三档
- Controller、Service 同步删除该参数

### 4. Balance/Checkout ¥NaN 兜底 → `7b43be1`
- `BalancePage`: `this.balance = Number.isFinite(user.balance) ? user.balance : 0`
- `CheckoutPage`: `selectedCoupon.amount.toFixed(2)` 加 `Number.isFinite` 守卫
- 充值回写 `updated.balance` 同处理

### 5. 分类同步 null TypeError → `d9f92ed`
- `syncCategoriesFromServer`: 三字段 `(remote.xxx ?? '').trim()`
- null 不再触发 TypeError 被 try/catch 吞掉
- 空串走原有 fallback 回退默认图标

### 6. 商户统计同步失败提示 → `927a717`
- `MerchantStatsPage.refreshRemoteStats` 加 try/catch
- `loadError` 状态驱动浅红横幅「数据加载失败 + 重试」
- 成功时自动清除，不需要手动解除

### 7. normalizeOrderList 补注释 → `98f4b3b`
- 函数无条件返回空数组是**有意设计**（订单只以服务端为准）
- 加 docstring 解释：本地恢复可能状态过期，每次进页面实时拉取

### 8. 支付倒计时用服务端时间戳 → `7d0113a`
- 后端 `OrderView` 新增 `payDeadlineEpochMs`（服务端毫秒时间戳）
- 前端 `computePayRemain` 去掉 `new Date(deadline.replace(...))` 解析
- 直接 `epochMs - Date.now()`，避免跨时区偏差

### 9. Outbox 去重原子化 → `0669e3e`
- 消费端 `hasKey` 检查 + `set` 写入 → `setIfAbsent` 原子抢占
- 短 TTL 5 分钟处理中锁 + 成功后 `expire` 延长到 `dedupHours`
- Outbox 中继加 `ponytail:` 注释说明多实例行级认领升级路径
