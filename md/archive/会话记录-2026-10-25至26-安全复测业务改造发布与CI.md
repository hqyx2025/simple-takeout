## 五、使用当前 Windows 电脑配置 runner

用户明确要求使用当前 Windows 电脑完成自托管 runner。该工作属于“诊断外卖业务与交互逻辑”会话的后续轮次。

- runner：`windows-deveco`；标签：`self-hosted / Windows / X64 / DevEco`；安装目录：`C:\actions-runner`。
- Windows 服务：`actions.runner.hqyx2025-simple-takeout.windows-deveco`，账户为 `NT AUTHORITY\NETWORK SERVICE`，配置延迟自动启动和故障恢复。
- 使用独立 `_work` 检出目录及已有 DevEco 工具链，不在日常开发工作区运行 checkout 清理。
- 解决服务账户缺少当前用户 Git 代理的问题，在 runner 私有 `.env` 配置相同本机代理；保持电脑唤醒、联网及代理可用。
- PowerShell 执行策略仅作用于 CI 步骤进程；补齐依赖安装、工具链检查、非零退出检查及产物上传。
- 三个旧脚本夹具同步当前接口契约：网络基址列表、后端定位代理、失败时保留本会话已确认地址并标记同步失败；保留冷启动与跨账号隔离检查。
- workflow 仅监听 `master` 相关文件 push 与手动运行，不监听公开仓库的 `pull_request`。
- 原排队旧任务取消，后续新任务实际构建与脚本检查成功；最终资料提交也自动触发 CI 并再次通过。
- 构建产物名为 `entry-unsigned-debug-hap`，在对应 GitHub Actions 记录中下载，保留 7 天；它是未签名 debug HAP，不是 AppGallery 发布包。

维护命令、路径与代理说明见 [开发参考](../开发参考.md) 的“Windows 自托管前端 CI”小节。截图证据：`TemporaryCacheStorage/runner-ci-success.jpg`。
