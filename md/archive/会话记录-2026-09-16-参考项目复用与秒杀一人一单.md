# 会话记录-2026-09-16-参考项目复用与秒杀一人一单

## 背景

拉取两个参考仓库（苍穹外卖 sky-take-out @ gitee、黑马点评 hmdp-plus @ gitee），通读后产出可用点差异报告；按优先级落地「秒杀三件套」（一人一单 / 访问令牌 / 订阅补发）中的「一人一单」，并在权威设计文档 `md/重构大纲提示词.md` 起「套餐与组合购」章节草案。

## 一、参考项目差异结论

- hmdp-plus（黑马点评 plus）= 过度工程化：Kafka + Redisson + MyBatis-Plus + 雪花 ID + 分库分表 + 布隆过滤器 + 对账。核心秒杀 = Lua 原子脚本（库存校验 → SISMEMBER 一人一单 → INCRBY → SADD → XADD stream）+ 异步消费者。
- 简单外卖现状：单品秒杀内嵌 `POST /api/orders`（自动套秒杀价 + `SeckillDao.deductQuota` 条件更新 `sold + n <= quota`），无独立抢购接口、无 per-user 限制。
- 结论：只取「一人一单」思路，用数据库唯一键实现（不引 Lua/Redisson——现有条件更新已保证不超卖，见 `md/权限边界与高并发审计.md`）。

## 二、秒杀三件套处置

- **一人一单（已落地）**：新增 `seckill_orders` 表 + `SeckillDao.joinOnce/releaseOnce`；`OrderService.doCreateOrder` 下单登记参与、`rollbackStock` 取消/超时/退款释放。
- **访问令牌（不落地）**：无独立秒杀入口；防重已被 idempotencyKey + order 限流（10/60s）+ 一人一单 三处覆盖。YAGNI。
- **订阅补发（不落地）**：名额满后回退原价而非「售罄排队」，无通知通道、无法自动补发（需地址/支付）。投入 > 收益，留作演进取。

## 三、一人一单实现要点

- `seckill_orders`：`UNIQUE KEY uk_seckill_user (user_id, seckill_id)`，`order_id` 默认 0，`create_time`。
- `joinOnce` = `INSERT IGNORE INTO seckill_orders(...) VALUES(...)`，rowcount == 1 才算成功；`releaseOnce` = `DELETE WHERE user_id = ? AND seckill_id = ?`。
- 下单 `orderDao.insert` 成功后遍历 holds，`seckillId > 0` 的调 `joinOnce`，失败抛 `BizException("该秒杀商品每人限购一次，请勿重复下单")`。
- 释放挂钩 `OrderService.rollbackStock`（与 `restoreQuota` 同生命周期）：取消 / 超时取消 / 管理端退款 / 退款审批四条路径都复用。
- 测试：`SeckillOnePerUserSqlTest`（3，钉 SQL 契约）+ `OrderServiceFlowTest`（2，秒杀价 8.0 生效 / 重复拒绝）+ `OrderBoundaryTest`（releaseOnce verify）。全量 156 测绿（原 151）。
