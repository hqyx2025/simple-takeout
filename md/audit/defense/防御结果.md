## 上线前必须处理的现有状态

本节保留迁移要求供复查；本次已经执行的内容以后一节部署记录为准。

1. **迁移配置。** 保持充值关闭、赠金为 0、验证码回传关闭、种子关闭。现有 `.env` 没有被改写，旧的危险配置或模板密钥会被新代码拒绝；不要通过取消守卫来恢复启动。
2. **分开生成三把密钥。** 每把使用独立的 `openssl rand -base64 32` 结果，分别配置 JWT、验证码 HMAC 和 AI 加密。新 JWT 格式及轮换会使旧会话失效；验证码应重新获取。已有 AI 配置加密数据需安全迁移，或在独立密钥配置后重新录入 API Key，不能直接假设旧密文可解密。
3. **处置历史账号和余额。** 复核／停用公开演示账号与未经平台开通的商户、骑手，重置旧弱口令；对演示充值余额及关联订单、托管款进行对账。源码封口不会自动修复历史资产。
4. **迁移数据库权限。** 已有 MySQL 卷需先创建并授权仅访问业务库的应用账号，配置独立 root 口令；Compose 的初始化变量只作用于新库，不要为此删除数据卷。Redis ACL 部署继续使用受控私有 ACL 文件。
5. **核对代理链。** `TAKEOUT_GATEWAY_TRUSTED_PROXY_REGEX` 必须匹配真正的宿主 Nginx／受控代理对端地址；demo 编排强制要求显式填写。裸跑应用时将 `TAKEOUT_INTERNAL_PROXY_REGEX` 收窄到实际网关，应用端口不得直接对公网发布。复测两个不同客户端的限流隔离及伪造头无效，不向线上打满封禁桶。
6. **初始化上传预算。** 新表由 schema 初始化；历史本地／OBS 文件须先盘点并补录 `upload_usage`，其中 user_id=0 表示全局已用量。配额为累计历史容量，达到上限后需要管理员清理／核账，不能无条件清零。存储成功但数据库提交失败仍可能遗留孤立对象，需在运维盘点中处理。
7. **完成目标环境复测。** 第一轮跳过的 MySQL／Redis 用例已在独立临时实例上补跑。目标版本容器、跨进程故障切换、真实 Redis 断连、OBS 上传、支付宝联调、设备实测、依赖 CVE／镜像扫描及线上回归仍未完成；本地并发用例不等于线上压力测试。
