**实际 Redis 键空间上界。** 同一 Redis DB、同一配置前缀下，全部 app 副本共享：

| 对象 | 新键名集合 | 最大不同键名数 |
| :--- | :--- | ---: |
| 所有浏览缓存值 | `takeout:hot:v2:0` 至 `takeout:hot:v2:511` | 512 |
| 对应回源锁 | 上述键名加 `:lock` | 512 |
| 合计 | 两个固定集合 | **1024** |

坐标、分类、ID、limit 和原始 double 半径都不能扩大这个物理集合。合法查询下最多可产生 **512 个不同缓存值键、1024 个值/锁键名**；完成请求释放锁后通常只有值键。业务查询身份仍可有很多种，但只作为值内标签，不能再按请求数增长 Redis 键数。

每个编码值（包含查询标签与载荷）的 UTF-8 长度最多 65536 字节，因此全部值的编码载荷合计最多 `512 × 65536 = 33554432` 字节，即 **32 MiB**。这不包含 Redis 对象、键名、锁、分配器及网络/AOF 开销，也不是整个 Redis 的容量承诺。

```java
private static final int MAX_ENTRY_BYTES = 64 * 1024;
private record CacheEntry(String key, String value) {}

String storageKey(String businessKey) {
    return keyPrefix + "hot:v2:" + Math.floorMod(businessKey.hashCode(), CACHE_SLOTS);
}
```

```java
// 读取：必须属于同一个完整查询身份，才能反序列化为业务结果。
```

