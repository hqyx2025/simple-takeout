### RT-31

**B · 接受风险。** 保留进程级健康短路，补充 [README.md](D:/work/jiandanwaimai/README.md:273) 273–288 行的首次失败行为、全部登录身份作用域、故障续期、N 倍配额及带外处置。没有实现按身份冷却，也没有让未知身份在故障时一律拒绝。

1. **影响谁：** 当前四类登录桶涉及的全部来源 IP 和账号，尤其是本副本尚未观察到其他副本封禁的身份。已存在的本地封禁仍拒绝，支付密码、下单等其他动作不使用该登录短路。
2. **触发条件：** 任一当前登录 Redis 调用异常，或耗时达到 250 ms。没有已知本地封禁时，出错的 `isBlocked` 本次返回未封禁；随后仍须经过本地预算、CPU 准入和真实凭据验证。一次瞬时异常即使已恢复，也不会提前取消本轮冷却。
3. **时间与范围：** 作用域是本进程全部登录身份。每轮冷却 5 秒，单探测继续慢/失败就续期，故可覆盖整个故障期间，**没有固定总时长上限**。多副本降级时有 N 份本地预算；主 Compose N=2，对应两份。窗口切换、切换前已消耗的 Redis 预算和反复重启不能被这张配额表当成统一猜测次数上界。
4. **带外补救：** 既有 root SSH 运维可排查 Redis/连接池并确认恢复，等冷却到期后的快速探测恢复共享判断；维护窗口也可减少 app 副本并核验健康。恢复过程不补写本地计数。管理员仍可用既有恢复脚本清目标键并重启全部 app，但本地窗口丢失、在途请求中断的 RT-22 代价保留。没有执行这些运维动作。
5. **接受理由：** Redis 及连接池是共享资源，按身份冷却不能阻止换 IP/手机号的请求反复承担慢 I/O。对未知身份一律拒绝会让首次登录用户在故障期间无法登录。当前保留可继续服务的有界本地保护，接受明确列出的预算放大，不下调本项定级；主 Compose 多副本条件下按 Medium 接受，当前 demo 编排单副本条件下按 Low 接受。

### RT-32

**B · 接受风险。** 修改 [README.md](D:/work/jiandanwaimai/README.md:275) 275 行，明确区分“从观察时刻保留一个完整政策时长”和“从原始 Redis 封禁开始的总时长”。没有实现剩余 TTL 镜像，也没有声称错峰观察已修复。

1. **影响谁：** 被来源或账号桶封禁的合法用户；即使 Redis 已解封，较晚观察到封禁的副本仍可能拒绝。单副本重启/部署后首次观察同样适用。
2. **触发条件：** 本地尚无有效封禁，首次在较晚时刻观察到仍存在的 Redis 封禁。当前代码从此刻起算完整 B，而不是读取剩余 TTL。
3. **时间上限：** 对同一次固定 Redis 封禁，首次观察发生在其到期前，额外延长小于一个完整 B，总时长可接近 **2B**。默认失败桶 B=600 秒，因此从最初封禁起可接近 **1200 秒**；总量桶 B=60 秒，可接近 120 秒。重复命中已有本地封禁不续期。攻击者继续制造新的封禁时，不提供从首次攻击起算的整体恢复期限。
4. **带外补救：** 目标管理员可使用既有 root SSH 恢复脚本清键并重启 app，承担 RT-22 代价。其他用户可等待本地期限；运维在确认 Redis 原封禁已到期后，可在维护窗口重启清掉镜像，但会丢失全部本地窗口并中断在途请求。Redis 封禁尚在时直接重启，可能再次观察并起算，不能当作无代价解封。
5. **接受理由：** 保留已观察封禁，避免短路后下一次请求立即放行；接受额外最多一个政策时长的延迟。当前没有读取剩余 TTL 的实现，本轮把这项代价与可达总时长写清，不下调 Low 定级。
