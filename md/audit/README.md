## 文档对话协议（第三至第十轮，现已结束）

双方不见面、不共享上下文，只通过 `md/audit/` 下的文件交换意见。规则：

| 轮次 | 谁写 | 写什么 | 文件 |
| --- | --- | --- | --- |
| 攻击 | 红队 | 逐条编号的发现 + 证据 + 明确要求（改 / 接受） | `round3/第三轮攻击-致防守方.md` |
| 防守 | 防守方 | 按同一编号逐条回应，**每条只能是"已修复+回归"或"接受风险+代价"** | 新建 `round3/第三轮防御-回复.md`（用 [模板](round3/第三轮防御-回复-模板.md)） |
| 攻击 | 红队 | 只针对上一轮**新写入的代码**与"接受风险"的边界做下一轮 | `round4/` |

约定：

1. **编号不重排**。RT-01..RT-15 属第二轮，RT-16.. 属第三轮，后续只追加。
2. **不接受概括句**。"整体已加固""风险可控"不算回应；每条要有文件:行号或命令输出。
3. **选"接受风险"必须写**：谁、在什么条件下、损失上限、是否有带外补救。
4. **不修也要留记录**，避免下一轮重复讨论同一条。
5. 红队线上仅做低频只读探测；终轮之后，防守方按用户另行明确授权执行部署与 QA 登录实验，范围和清理结果见终轮回复，不能用红队探测限制否认已授权的发布事实。

## 关于 cache/ 的两个提醒

- `cache/defense-round2/runtime-*/`、`cache/round2-redteam/auth-red/mysqldata/` 是**临时 MySQL 数据目录**，
  内含自动生成的 `*-key.pem`（仅用于本地回环测试实例，不含任何业务凭据），但体积很大且属于运行产物，
  已在 [cache/.gitignore](cache/.gitignore) 中整体排除。
- 这些缓存不是运行依赖，但用户已要求留存证据：本次不删除历史缓存、探针、测试日志、发布包、备份或文档原稿。它们也不是完整业务备份，不能替代服务器数据库与 Redis 的恢复材料。
