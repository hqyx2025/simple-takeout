## Q2 登录阈值的口径

- **10 次/分钟/出口 IP 是上一轮顺带定的数，不是已经确认的校园共享出口产品口径。** 当时把每次预占预算都算作失败，是本轮要纠正的实现。
- 当前目标为：来源认证失败 10 次/60 秒、封 600 秒；另设来源总请求 60 次/60 秒、封 60 秒。成功只占总量预算，不占来源失败预算。任何成功都不会 reset 来源失败计数或封禁，因而不会重开“自己的成功登录清别人的失败”路径。
- 失败计数发生在认证错误返回时。已越过预检的并发请求可以继续完成，所以不宣称一个来源并发时只会执行十次验密：其验密前上界由 60 次总量预算承担。单账号仍受 RT-16 中保留的十次验密前账号预算限制。
- **阈值可配置**，不是只在文档里写“可以调大”。[LoginRateLimiter.java:70](D:/work/jiandanwaimai/server/takeout-common/src/main/java/com/example/takeout/security/LoginRateLimiter.java:70) 从 Spring 属性读取；[application.yml:115](D:/work/jiandanwaimai/server/takeout-app/src/main/resources/application.yml:115) 绑定环境变量；[docker-compose.yml:98](D:/work/jiandanwaimai/docker-compose.yml:98) 向容器传入。修改部署环境变量并重建 app 容器环境后生效，不需要重新编译。启动时拒绝非正数、次数超过 10,000 或时间超过 86,400 秒的配置。

| 动作 | 次数环境变量及默认值 | 窗口环境变量及默认值 | 封禁环境变量及默认值 |
| --- | --- | --- | --- |
| 来源认证失败 `login` | `TAKEOUT_LOGIN_FAILURE_LIMIT=10` | `TAKEOUT_LOGIN_FAILURE_WINDOW_SECONDS=60` | `TAKEOUT_LOGIN_FAILURE_BLOCK_SECONDS=600` |

账号准入目前仍计每次验密前尝试，包括成功；它没有被称为“账号失败预算”。同一账号短时间多次正常登录也可能触发它，这项代价归入 RT-16 的 B，不藏进 RT-17 的修复结论。

public ResponseEntity<ApiResponse<Void>> handleHttpStatus(org.springframework.web.ErrorResponseException e) {
    int code = e.getStatusCode().value();
    if (code >= 500) log.error("服务器 HTTP 错误 status={}", code, e);
    String message = code == 404 ? "资源不存在" : code < 500 ? "请求参数或操作不正确" : "服务器内部错误，请稍后重试";
    return ResponseEntity.status(e.getStatusCode()).body(ApiResponse.error(code, message));
}
