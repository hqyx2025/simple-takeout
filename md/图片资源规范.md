# 图片资源规范

> 目的：所有图片（静态资源 + 商户/用户上传图）都有唯一、可预期的位置与引用方式，禁止再出现"图片不知道存到哪去了""用户端看不到图"。

## 1. 三类图片，三个位置

| 类别 | 存放位置 | 引用方式 | 命名 |
| --- | --- | --- | --- |
| 新增图标、插图、占位图（SVG） | `entry/src/main/resources/base/media/` + `dark/media/` | `$r('app.media.xxx')` | 小写下划线、语义化，深浅色同名 |
| 随资源限定符变化的图（应用图标/启动图） | `entry/src/main/resources/base/media/` | `$r('app.media.xxx')` | 同上（资源名只能小写字母数字下划线） |
| 运行时上传图（商户商品图、评价图） | 后端 `takeout.upload.dir`（默认 `uploads/`） | 后端返回相对地址 `/uploads/yyyyMMdd/xxx.png`，前端拼 `API_CONFIG.BASE_URL` | UUID 文件名，按天分目录 |

### 上传图到底存在哪

| 运行方式 | 落盘位置 | 说明 |
| --- | --- | --- |
| 本机 `mvn -f server/pom.xml spring-boot:run` | 仓库 `server/uploads/` | 已在 `.gitignore`，不入库 |
| Docker Compose 单机双实例 | Compose 卷 `<项目名>_uploads-data` → 每个 app 的 `/app/uploads` | 两个副本共用，不迁移对象存储；查看：`docker compose exec --index 1 app ls -R /app/uploads` |

仅适用于单 Docker 主机。MySQL 月度 SQL 备份不包含图片文件，上传卷应另行备份；`docker compose down -v` 会删除上传卷。

对外访问地址统一是 `{API_CONFIG.BASE_URL}/uploads/...`（模拟器即 `http://10.0.2.2:8087/uploads/...`），`WebConfig` 把 `/uploads/**` 映射到本地目录且**不需要 JWT**。

## 2. 静态图目录树（image 分类）

```
entry/src/main/resources/
├── base/media/food_placeholder.svg  # 浅色默认商品插图
└── dark/media/food_placeholder.svg  # 深色默认商品插图
```

新绘素材直接使用 SVG，采用登录页的线宽与暖色；商品照片和用户上传内容保留原始内容。

## 3. 硬性规则

1. 图片不许丢在仓库根目录，也不许丢在业务源码目录；临时产物进 `TemporaryCacheStorage/`（已忽略、可整体删除）。
2. 前端渲染商户/商品图片**一律**用 `common/Constants.ets` 的 `merchantImageSource(image)`：
   - 空值 → 返回 `DEFAULT_MERCHANT_IMAGE`（默认占位图），不会再渲染空白或文字占位；
   - `/uploads/...` 相对地址 → 拼 `API_CONFIG.BASE_URL`；
   - `http(s)://` 开头 → 原样返回。
   同时在 `Image` 上加 `.alt(DEFAULT_MERCHANT_IMAGE)`，兜住"地址存在但文件已删"的加载失败。
3. 新增图标、插图直接绘制 SVG，放入 `base/media/` 与 `dark/media/`，使用同名资源自动适配主题；通用兜底通过 `Constants.ets` 引用。
4. 替换默认占位图只需覆盖 `food_placeholder.svg`，所有渲染点自动生效（没有散落的硬编码路径）。
5. 上传图不写进前端包，也不写死在页面里；地址永远来自后端字段。
