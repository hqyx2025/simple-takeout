# 图片资源规范

> 目的：所有图片（静态资源 + 商户/用户上传图）都有唯一、可预期的位置与引用方式，禁止再出现"图片不知道存到哪去了""用户端看不到图"。

## 1. 三类图片，三个位置

| 类别 | 存放位置 | 引用方式 | 命名 |
| --- | --- | --- | --- |
| 应用内静态图（占位图/插图） | `entry/src/main/resources/rawfile/images/<用途>/` | `$rawfile('images/<用途>/<文件>')` | 小写下划线、语义化 |
| 随资源限定符变化的图（应用图标/启动图） | `entry/src/main/resources/base/media/` | `$r('app.media.xxx')` | 同上（资源名只能小写字母数字下划线） |
| 运行时上传图（商户商品图、评价图） | 后端 `takeout.upload.dir`（默认 `uploads/`） | 后端返回相对地址 `/uploads/yyyyMMdd/xxx.png`，前端拼 `API_CONFIG.BASE_URL` | UUID 文件名，按天分目录 |

### 上传图到底存在哪

| 运行方式 | 落盘位置 | 说明 |
| --- | --- | --- |
| 本机 `mvn -f server/pom.xml spring-boot:run` | 仓库 `server/uploads/` | 已在 `.gitignore`，不入库 |
| `docker compose`（当前设备联调用的就是这个，后端 9000） | docker volume `jiandanwaimai_uploads-data` → 容器内 `/app/uploads` | 重建容器不丢图；查看：`docker exec takeout-app ls -R /app/uploads` |

对外访问地址统一是 `{API_CONFIG.BASE_URL}/uploads/...`（模拟器即 `http://10.0.2.2:9000/uploads/...`），`WebConfig` 把 `/uploads/**` 映射到本地目录且**不需要 JWT**。

## 2. 静态图目录树（image 分类）

```
entry/src/main/resources/rawfile/images/
├── default/                              # 兜底占位：数据缺失或加载失败时展示
│   └── merchant_goods_default.png        # 商户上传图片默认占位
└── <用途>/                               # 按用途再分子目录，如 banner/ category/
```

## 3. 硬性规则

1. 图片不许丢在仓库根目录，也不许丢在业务源码目录；临时产物进 `TemporaryCacheStorage/`（已忽略、可整体删除）。
2. 前端渲染商户/商品图片**一律**用 `common/Constants.ets` 的 `merchantImageSource(image)`：
   - 空值 → 返回 `DEFAULT_MERCHANT_IMAGE`（默认占位图），不会再渲染空白或文字占位；
   - `/uploads/...` 相对地址 → 拼 `API_CONFIG.BASE_URL`；
   - `http(s)://` 开头 → 原样返回。
   同时在 `Image` 上加 `.alt(DEFAULT_MERCHANT_IMAGE)`，兜住"地址存在但文件已删"的加载失败。
3. 新增静态图：放进对应 `rawfile/images/<用途>/` 子目录 → 在本文件第 4 节登记 → 若是通用兜底再在 `Constants.ets` 加常量。
4. 替换默认占位图只需覆盖 `merchant_goods_default.png`，所有渲染点自动生效（没有散落的硬编码路径）。
5. 上传图不写进前端包，也不写死在页面里；地址永远来自后端字段。
