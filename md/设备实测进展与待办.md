## 四、待判定项（下一轮的首要任务，已写成可执行的断言计划）

### 疑点 3：搜索页中文输入无结果 / 返回疑似无效
- 现象：`uitest dumpLayout` 看到 `SearchPage` 有 `TextInput`（第 76 行）与 `doSearch()`（第 85 行 onClick）；但 `uiInput inputText 黄焖鸡` 后无结果、历史搜索也未写入；`keyEvent 2` 与页内「‹」点击都未能离开该页。
- 已知实现事实：该页是**点按钮才检索**（不是输入即搜）；`inputText` 传中文很可能被 PowerShell→hdc 参数编码破坏。
- 判定方法（写成 `SearchFlow.test.ets`）：
  1. 首页点搜索栏 → 断言进入 `pages/SearchPage`；
  2. 点「‹」→ 断言回到 `pages/Index`（若断言失败 = **真 Bug：搜索页退不出**）；
  3. 输入关键词 + 点「搜索」→ 断言出现结果列表或明确空态提示（无反馈即 Bug）。

### 疑点 4：多规格加购行数 +1 但服务端无 `POST /api/cart/items`
- 现象：点「加入购物车」后购物车行数 2→3、界面「去结算(1)→(3)」，但服务端日志里 `POST /api/cart/items` **一次都没有**（只有 21:20:18 的 `PUT /api/cart/items/277`）。
- 无法排除：我的点击是否真的命中弹窗按钮 / 是否重复触发（1→3 提示可能加了 2 次）。
- 判定方法（写成 `SpecOrder.test.ets`）：
  1. 分类列表 → 黄焖鸡米饭（唯一有多规格菜品的店，store id=1，菜品 招牌套餐 有 标准份 48.5 / 大份 51.5 / 双人份 56.5）；
  2. 断言「选规格」存在 → 点开 → 断言三种规格名/价格/剩余份数；
  3. 点「大份」→ 断言「数量」步进器出现；
  4. `hilog -r` → 点「加入购物车」→ 读应用侧日志断言**只调用一次** `addCartItemRemote`，并对照服务端只出现一次 `POST /api/cart/items`、购物车行数恰好 +1；
  5. 若 0 次调用而行数变化 = **更严重的 Bug**（绕过服务端权威数据）；若 2 次 = 重复加购（查弹窗 `submit()` 是否被父级 onClick 二次触发、`submitting` 防重是否失效）。

> 注意：多步坐标点击链**极不可靠**（Round 3–6、10 连续卡在这里），后续一律用 UiTest 组件匹配器写用例，不要再靠坐标串联。

## 八、驱动脚本的坑（务必避免，已各踩一次）

1. **中文入参**：`hdc shell uitest uiInput inputText 黄焖鸡` 会被 PowerShell→hdc 的参数编码破坏 → 不要用它输入中文，改用组件匹配或换英文/数字关键词；
2. **`Join-String` 在 PS 5.1 不存在** → 用 `-join ' | '`；
3. **字符串里嵌套双引号**会让整段脚本解析失败（本次第 26 轮整轮白跑）→ 中文提示语一律用单引号，且不要在双引号字符串里嵌 `"`；
4. **坐标匹配跨节点**：`"bounds":"..."[\s\S]{0,1400}?"text":"目标"` 会跨到下一个节点，把"取消订单"的 bounds 配给"立即支付"→ 跨度收到 700 并用 `$ms[$ms.Count-1]` 取最后一个匹配；
5. **`dumpLayout` 抓不到 toast**（独立窗口）→ 提示类断言改用 hilog 或"后端是否收到请求"；
6. **导航栈卡死时**用 `aa force-stop` + `aa start` 重置，比找返回键可靠；
7. 读服务端日志时**不要用文件偏移增量**，直接用 `hilog -x | grep TakeoutApp` 读应用侧请求日志更可靠。
