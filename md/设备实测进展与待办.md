## 一、环境与可复用命令（均已验证可用）

```powershell
# 0) 前置：后端必须先起（模拟器用 10.0.2.2 访问宿主机）
$env:JAVA_HOME="C:\Program Files\Java\jdk-25.0.2"; mvn -f server/pom.xml spring-boot:run

# 1) 一键：启动模拟器(-noWindow) → 构建 → 安装 → 拉起 → 截图 → 读界面文本
powershell -ExecutionPolicy Bypass -File scripts/device-test.ps1 -Start
powershell -ExecutionPolicy Bypass -File scripts/device-test.ps1 -Dump     # 只读当前界面
powershell -ExecutionPolicy Bypass -File scripts/device-test.ps1 -Stop     # 关闭模拟器

# 2) 设备端 UiTest（组件匹配器驱动；一条命令跑完 构建→安装→拉起→跑用例→判定）
#    注意：-Class 一次只跑一个用例类，每个类的**前置状态不同**，聚合跑（不带 -Class）没有意义
powershell -ExecutionPolicy Bypass -File scripts/device-uitest.ps1 -Build -Class Probe -GrantLocation
powershell -ExecutionPolicy Bypass -File scripts/device-uitest.ps1 -Class LoginFlow -GuestClean -GrantLocation
powershell -ExecutionPolicy Bypass -File scripts/device-uitest.ps1 -Class LocationFlow -SkipInstall -GrantLocation
powershell -ExecutionPolicy Bypass -File scripts/device-uitest.ps1 -Class SearchFlow -SkipInstall
# 结算页负路径 + 待付款订单回归（自带 fixture、构建安装、host 侧数字核对；-WithGuard 先跑 CheckoutGuard）
powershell -ExecutionPolicy Bypass -File scripts/device-checkout-regression.ps1 -WithGuard

# 3) 应用自身日志（比解析 maven 重定向日志可靠；先清空再复现）
& $hdc shell hilog -r
& $hdc shell "hilog -x | grep TakeoutApp | tail -30"
& $hdc shell "hilog -x | grep -c 'POST /api/orders'"      # 计数用设备侧 grep -c，不要读文件偏移

# 4) 界面结构（结构化解析：正则跨节点会把 bounds 配错节点）
& $hdc shell uitest dumpLayout -p /data/local/tmp/layout.json
& $hdc file recv /data/local/tmp/layout.json TemporaryCacheStorage/agent-ui-layout.json
powershell -ExecutionPolicy Bypass -File scripts/ui-dump.ps1            # page + 每个文本/id/bounds
powershell -ExecutionPolicy Bypass -File scripts/ui-dump.ps1 -Match 'cart'   # 只列关心的节点
```

要点：模拟器**不校验发布签名**，unsigned HAP（含 ohosTest 包）可直接 `hdc install`；模拟器**必须 `-noWindow`** 启动。
**关键前提**：`aa test` 会把测试 Ability 的 “Hello World” 页拉到前台盖住应用，所以**每个用例都必须自己把应用拉起来**
（`UiTestHelper.launchAppUnderTest` 用 `AbilityDelegator.startAbility`）；不这么做的话 `findComponent` 只会返回 null。

## 四、待判定项（下一轮的首要任务，已写成可执行的断言计划）

### 疑点 3：搜索页中文输入无结果 / 返回疑似无效
- 现象：`uitest dumpLayout` 看到 `SearchPage` 有 `TextInput`（第 76 行）与 `doSearch()`（第 85 行 onClick）；但 `uiInput inputText 黄焖鸡` 后无结果、历史搜索也未写入；`keyEvent 2` 与页内「‹」点击都未能离开该页。
- 已知实现事实：该页是**点按钮才检索**（不是输入即搜）；`inputText` 传中文很可能被 PowerShell→hdc 参数编码破坏。
- 判定方法（写成 `SearchFlow.test.ets`）：
  1. 首页点搜索栏 → 断言进入 `pages/SearchPage`；
  2. 点「‹」→ 断言回到 `pages/Index`（若断言失败 = **真 Bug：搜索页退不出**）；
  3. 输入关键词 + 点「搜索」→ 断言出现结果列表或明确空态提示（无反馈即 Bug）。

### 疑点 4：多规格加购行数 +1 但服务端无 `POST /api/cart/items`
- 现象：点「加入购物车」后购物车行数 2→3、界面「去结算(1)→(3)」，但服务端日志里 `POST /api/cart/items` **一次都没有**（只有 21:20:18 的 `PUT /api/cart/items/277`）。
- 无法排除：我的点击是否真的命中弹窗按钮 / 是否重复触发（1→3 提示可能加了 2 次）。
- 判定方法（写成 `SpecOrder.test.ets`）：
  1. 分类列表 → 黄焖鸡米饭（唯一有多规格菜品的店，store id=1，菜品 招牌套餐 有 标准份 48.5 / 大份 51.5 / 双人份 56.5）；
  2. 断言「选规格」存在 → 点开 → 断言三种规格名/价格/剩余份数；
  3. 点「大份」→ 断言「数量」步进器出现；
  4. `hilog -r` → 点「加入购物车」→ 读应用侧日志断言**只调用一次** `addCartItemRemote`，并对照服务端只出现一次 `POST /api/cart/items`、购物车行数恰好 +1；
  5. 若 0 次调用而行数变化 = **更严重的 Bug**（绕过服务端权威数据）；若 2 次 = 重复加购（查弹窗 `submit()` 是否被父级 onClick 二次触发、`submitting` 防重是否失效）。

> 注意：多步坐标点击链**极不可靠**（Round 3–6、10 连续卡在这里），后续一律用 UiTest 组件匹配器写用例，不要再靠坐标串联。

## 八、驱动脚本的坑（务必避免，已各踩一次）

1. **中文入参**：`hdc shell uitest uiInput inputText 黄焖鸡` 会被 PowerShell→hdc 的参数编码破坏 → 不要用它输入中文，改用组件匹配或换英文/数字关键词；
2. **`Join-String` 在 PS 5.1 不存在** → 用 `-join ' | '`；
3. **字符串里嵌套双引号**会让整段脚本解析失败（本次第 26 轮整轮白跑）→ 中文提示语一律用单引号，且不要在双引号字符串里嵌 `"`；
4. **坐标匹配跨节点**：`"bounds":"..."[\s\S]{0,1400}?"text":"目标"` 会跨到下一个节点，把"取消订单"的 bounds 配给"立即支付"→ 跨度收到 700 并用 `$ms[$ms.Count-1]` 取最后一个匹配；
   （更好的做法：用 `scripts/ui-dump.ps1` 直接解析 JSON 树，不再写正则）
5. **`dumpLayout` 抓不到 toast**（独立窗口）→ 提示类断言改用 hilog 或"后端是否收到请求"；
6. **导航栈卡死时**用 `aa force-stop` + `aa start` 重置，比找返回键可靠；
7. 读服务端日志时**不要用文件偏移增量**，直接用 `hilog -x | grep TakeoutApp` 读应用侧请求日志更可靠；
8. **`findComponent` 未命中返回 `null`（不是 `undefined`）**：`expect(comp !== undefined).assertTrue()` 在未命中时恒真 → 用例空跑还报 Pass。
   统一用 `UiTestHelper.isFound()` / `requireComponent()`（后者同时把类型收窄，否则 `.click()` 会报 `'x' is possibly 'null'` 编译不过）；
9. **`aa test` 会把测试 Ability 的 Hello World 页盖在应用上**：不先 `AbilityDelegator.startAbility(EntryAbility)` 的话驱动只能看到测试页，任何查找都返回 null。
   证据：`[Probe] id=tab-3 found=false / Text component count=5`，并发 `dumpLayout` 得到 `testability/pages/Index` + `Hello World`。
   `scripts/device-uitest.ps1 -Class Probe` 就是这条的守卫用例；
10. **别靠「按返回退到首页」给用例复位**：在隐私同意页/登录页上按返回会把应用直接退到桌面，后续断言全部找不到控件（LoginFlow 因此红过一次）。
    正确做法是 host 侧 `aa force-stop` + `aa start`（进程重启后页面栈从 `pages/Index` 重来）；
11. **Component 句柄会失效**：购物车行的 ForEach key 带 `cartRenderVersion`，点一次 `+` 触发刷新 → 整棵行子树重建 → 上次拿到的句柄再点就报
    `... does not exist on current UI! (NoCandidates)`。统一用 `clickByIdOrText()`（每次点击前重新查找 + 重试）；
12. **系统权限弹窗会遮住应用**：清数据后首次进定位页会弹定位权限框，此时 UiTest 报 `window is covered`、什么都找不到。
    用 host 侧预授权：`$tokenId = (bm dump -n <bundle> | grep accessTokenId)` → `atm perm -g -i $tokenId -p ohos.permission.LOCATION`（`APPROXIMATELY_LOCATION` 同理）；
13. **`$ErrorActionPreference='Stop'` 会让构建"莫名失败"**：hvigor 往 stderr 写进度，PS 5.1 下原生命令写 stderr 即变成 terminating error → 脚本里用 `Continue`，成功与否另行判断；
14. **判断"产物是否最新"不能拿构建开始时间比**：主模块 `UP-TO-DATE` 时 HAP 时间戳不会更新 → 应按**各自模块的源码时间**比对（`entry\src\main` / `entry\src\ohosTest`）。
