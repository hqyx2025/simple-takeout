# 14 - 日志服务模块业务逻辑

> 涉及文件：`entry/src/main/ets/service/AppLogger.ets`、`entry/src/main/ets/entryability/EntryAbility.ets`

## 一、功能概述

统一日志服务（AppLogger）：控制台 + 文件双输出；日志文件按天分文件；单文件超过 2MB 自动压缩归档 zip 并新建文件。所有业务模块通过 `logInfo / logWarn / logError` 埋点。

## 二、业务逻辑判断

### 1. 初始化（`initLogger()`）

```
前置条件：appContext 必须已写入 AppStorage（EntryAbility.onCreate 中先 setOrCreate 再调用）
判断：appContext 是否有效
  ├─ 无效 → console.error + 直接 return（loggerReady=false，日志功能降级为仅控制台）
  └─ 有效 → 初始化：
      1. logDirPath = filesDir + '/log'（不存在则 mkdirSync 创建，已存在忽略异常）
      2. currentDateKey = 今天日期(YYYY-MM-DD)
      3. logFilePath = log/app-YYYY-MM-DD.log
      4. loggerReady = true
```

| 判断项 | 规则 | 结果 |
|---|---|---|
| appContext 缺失 | 未设置或为 null | 初始化失败，仅控制台输出 |
| 目录创建 | mkdirSync(recursive) | 已存在时忽略异常 |
| 文件命名 | `app-YYYY-MM-DD.log` | 按天分文件 |

### 2. 写入前轮转检查（`checkRotation()`）

```
触发：每次 writeToFile 前
判断1：跨天（today !== currentDateKey）
  ├─ 是 → 切换 logFilePath 为新日期文件（旧文件保留）
  └─ 否 → 判断2
判断2：文件大小 >= MAX_LOG_SIZE（2MB）
  ├─ 是 → archiveCurrentFile()（压缩归档 + 换新文件）
  └─ 否 → 继续写入当前文件
```

### 3. 压缩归档（`archiveCurrentFile()`）

```
流程：
  1. rename 当前日志文件 → .old（避免压缩期间写入冲突）
  2. logFilePath 切换为新文件：app-YYYY-MM-DD-<时间戳>.log
  3. 异步 zlib.compressFile(.old → app-YYYY-MM-DD-<时间戳>.zip)
     ├─ 成功 → unlinkSync 删除 .old
     └─ 失败 → 保留 .old（Error 日志）
```

> 使用 `@ohos.zlib` 的 `compressFile`，options 传类型化空对象 `{}: zlib.Options`（所有字段可选，默认压缩参数）。

### 4. 日志输出（`log(level, tag, message)`）

```
输出1（控制台）：
  Error → console.error / Warn → console.warn / 其他 → console.info
  格式：[TakeoutApp][Level][Tag] message
输出2（文件）：
  writeToFile(level, `[Tag] message`)，行格式：
  [YYYY-MM-DD HH:mm:ss.SSS][Level] message
写入方式：openSync(READ_WRITE|CREATE|APPEND) → writeSync → closeSync
```

### 5. 三个对外接口

| 接口 | 级别 | 用途 |
|---|---|---|
| `logInfo(tag, message)` | Info | 关键业务操作成功（登录/下单/收藏等） |
| `logWarn(tag, message)` | Warn | 非致命异常（登录失败/状态不符/解析失败） |
| `logError(tag, message, detail?)` | Error | 致命异常（持久化失败/初始化失败），可带 detail 对象 |

## 三、轮转策略总结

| 触发条件 | 处理 | 产物 |
|---|---|---|
| 跨天 | 切换新文件 | `app-YYYY-MM-DD.log`（旧文件保留） |
| 超 2MB | 压缩归档 | `app-YYYY-MM-DD-<ts>.zip` + 新 log 文件 |

## 四、边界与异常处理

| 场景 | 处理方式 |
|---|---|
| 日志目录不存在 | 首次写入自动创建（initLogger 已建） |
| 文件首次写入前 stat 报错 | catch 忽略（正常） |
| 压缩失败 | Error 日志 + 保留 .old 文件 |
| 删除 .old 失败 | catch 忽略（不阻塞） |
| loggerReady=false | writeToFile 直接 return（仅控制台） |
| 打开/写入文件异常 | catch → Error 日志，finally 关闭句柄 |

## 五、数据流向

```
业务代码 → logInfo/logWarn/logError
  → log() → console（DevEco Log 窗口 / hdc hilog）
  → writeToFile → 沙箱 filesDir/log/app-YYYY-MM-DD.log
  → 超 2MB → zip 归档（@ohos.zlib）
```

> 日志文件位置：应用沙箱 `filesDir/log/`，可通过 DevEco Device File Manager 或 `hdc file recv` 导出。
