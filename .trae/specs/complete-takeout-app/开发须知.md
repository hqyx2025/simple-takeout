## 零、Git 工作流规范（强制执行）

### 远程仓库
- **Gitee 地址**：`https://gitee.com/pengzhiqiang87/simple-takeout.git`
- 每完成一个小功能（SubTask 级别）**必须**提交并推送到 Gitee

### 提交规范
- **提交粒度**：每完成一个 SubTask（子任务）即提交一次，不要积攒多个功能后一次性提交
- **Commit Message 格式**：`<type>(<scope>): <description>`
  - type：`feat`（新功能）/ `fix`（修复）/ `refactor`（重构）/ `style`（样式）/ `docs`（文档）
  - scope：模块名，如 `search` / `address` / `checkout` / `order` / `merchant`
  - description：中文简述
  - 示例：`feat(search): 实现搜索页热门词与历史搜索功能`
- **提交流程**（每完成一个 SubTask 后执行）：
  ```bash
  git add <具体文件路径>      # 不要用 git add . 避免提交无关文件
  git commit -m "feat(scope): 描述"
  git push origin <当前分支>
  ```
- **分支策略**：在 `master` 分支上直接开发（毕设项目，单人开发）
- **禁止事项**：
  - ❌ 禁止 `git push --force`
  - ❌ 禁止提交 `build/` 目录和 `.preview/` 目录（已在 .gitignore 中排除）
  - ❌ 禁止一次提交多个不相关功能
  - ❌ 禁止不写 commit message 或写无意义的 message

### 首次配置检查
开始编码前先检查远程仓库是否已配置：

```bash
git remote -v
```
若无远程仓库，需添加：

## 二、ArkTS 严格约束（违反即编译报错）

### 2.1 类型约束
- **禁止无类型对象字面量**：ArkTS 不允许 `{ key: value }` 裸对象字面量，会触发 `arkts-no-untyped-obj-literals`。必须：
  - 定义 `interface` 或 `class` 后再创建实例
  - 或使用 class 的 `static create()` 工厂方法（参考现有 `QuickEntryItem.create()`、`OrderTabItem.create()`）
- **禁止 `any` / `unknown`**：所有变量、参数、返回值必须有明确类型
- **禁止函数表达式作为回调类型不匹配**：回调参数类型必须严格对齐
- **Record 的 key 类型限制**：`Record<string, T>` 可以用，但 `Record<number, T>` 在某些场景会报错，优先用 `string` key 或 `Map`

### 2.2 UI 组件约束
- **`ShadowOptions.offsetY`** 必须为 `number` 类型，不能是 `'2vp'` 等字符串。建议直接去掉 `.shadow()` 调用，避免类型错误
- **`LengthMetrics`** 属性（如 `position`、Flex `space`）必须用 `LengthMetrics.vp(8)` 而非裸数字 `8`
- **`borderRadius`** 接受 `number` 或 `Length`，项目中统一用 `number`（通过 `BORDER_RADIUS` 常量）
- **`@Builder` 方法参数**：不能有默认值，参数类型必须显式声明
- **`@Component` struct**：不能有构造函数，状态变量用 `@State` / `@Prop` / `@Link` / `@StorageLink` 装饰
- **条件渲染** `if/else` 必须在 `build()` 内的最外层容器内，不能裸露在 `build()` 根级

### 2.3 配置文件约束
- **`main_pages.json`** 只允许 `src` 和 `window` 两个属性，**禁止** `routerMap`（属于 `router_map.json`）
  ```json
  // ✅ 正确
  { "src": ["pages/Index", "pages/SearchPage"] }
  // ❌ 错误
  { "src": ["pages/Index"], "routerMap": [...] }
  ```
- **`module.json5`** 权限配置在 `module.requestPermissions` 数组中

## 三、防幻觉清单（AI 编程高发错误）

### 3.1 禁止臆造 API
- **禁止使用不存在的 ArkUI 组件或属性**。如不确定某 API 是否存在，必须先查现有代码或官方文档
- **禁止臆造 import 路径**。所有 import 必须指向真实存在的文件或 @ohos / @kit 系统库
- **禁止臆造第三方库方法**。如使用 `@ohos/axios`，其 API 与标准 axios 一致，但不可臆造鸿蒙特有方法
- **系统库 import 规范**：
  - ✅ `import { http } from '@kit.NetworkKit'`（API 11+ 推荐）
  - ✅ `import http from '@ohos.net.http'`（旧式，仍可用）
  - ✅ `import preferences from '@ohos.data.preferences'`
  - ✅ `import { relationalStore } from '@kit.ArkData'`（API 11+）
  - ❌ 不要臆造 `@ohos.xxx.xxx` 格式的 import，不确定时用 @kit 形式

### 3.2 禁止假数据
- **唯一数据源**：所有模拟数据必须来自 `service/MockDataService.ets` 或 `service/AppStorageManager.ets`，**禁止在页面组件中硬编码新数据**
- **禁止臆造测试账号**：项目中已有的测试账号（密码均为 `123456`）：
  - 用户：`13800138000`（美食家小张）
  - 用户：`13900139000`（小王）
  - 商户：`13600136000`（黄焖鸡老板，拥有店铺1-5）
  - 商户：`13700137000`（串串香老板，拥有店铺6-8）
  - 商户：`13500135000`（甜品店老板，拥有店铺9-10）
- **禁止臆造图片URL**：项目中图片用占位符（首字母色块）或空字符串，**禁止编造网络图片URL**
- **禁止臆造 API 端点**：`HttpClient.ets` 当前对接本地 Mock，不可编造 `https://api.xxx.com` 等假地址
- 新增 Mock 数据时，必须在 `MockDataService.ets` 中添加导出函数，不可散落在页面中

## 四、代码风格规范（必须遵循现有模式）

### 4.1 常量使用
所有颜色、间距、字体、圆角必须从 `common/Constants.ets` 引入，**禁止硬编码**：
```typescript
// ✅ 正确
import { COLORS, SPACING, FONT_SIZE, BORDER_RADIUS } from '../common/Constants'
.fontSize(FONT_SIZE.LG)
.fontColor(COLORS.TEXT_PRIMARY)
.padding(SPACING.MD)

// ❌ 错误
.fontSize(16)
.fontColor('#333333')
.padding(12)
```

### 4.2 对象创建模式
需要对象字面量时，必须用 class + static create()：
```typescript
// ✅ 正确
class MyItem {
  id: number = 0
  name: string = ''
  static create(id: number, name: string): MyItem {
    let item = new MyItem()
    item.id = id
    item.name = name
    return item
  }
}

// ❌ 错误（arkts-no-untyped-obj-literals）
const items = [{ id: 1, name: 'a' }, { id: 2, name: 'b' }]
```

### 4.3 页面结构模板
```typescript
import { COLORS, SPACING, FONT_SIZE, BORDER_RADIUS } from '../common/Constants'
// 其他 import...

@Component
export struct XxxPage {
  @State loading: boolean = false
  // 状态变量...
  
  aboutToAppear() {
    // 初始化数据，调用 AppStorageManager 或 MockDataService
  }
  
  build() {
    Column() {
      // 导航栏
      // 内容区
      // 操作区
    }
    .width('100%')
    .height('100%')
    .backgroundColor(COLORS.BG_PRIMARY)
  }
  
  @Builder
  XxxBuilder(param: ParamType) {
    // 复用UI块
  }
}
```

### 4.4 状态管理规范
- 跨页面共享数据：用 `AppStorage` + `@StorageLink` / `@StorageProp`
- 页面内状态：用 `@State`
- 父子传值：`@Prop`（单向）/ `@Link`（双向）
- **PersistenceV2 持久化**：登录态、购物车、订单、收藏等关键数据需持久化时，在 `AppStorageManager.ets` 统一管理
